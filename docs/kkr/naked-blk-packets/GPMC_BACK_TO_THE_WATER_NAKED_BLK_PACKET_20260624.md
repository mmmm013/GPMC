## Two-Lane Processing Requirement

### Lane 1 — Formal Lineage BLK / KK Lane

Lane 1 must preserve:

- source audio identity
- title/provenance history
- composer / lyricist
- publisher / PRO lineage
- original track sequence
- BLK order
- section boundaries
- contiguous-source rules
- formal LT-PIX relationship

Formal KKs and KK-Kombos must stay tied to the original source sequence.

KK-Kombos may only be sold as one item when the source sections are contiguous.

### Lane 2 — Naked BLK / Naked KK Lane

Lane 2 must process each eligible BLK as its own naked candidate.

Naked processing strips front-end descriptive metadata and re-runs the BLK / KK through KKr as a new customer-facing unit.

Naked processing may ignore the song title for front-end use.

Naked processing may create its own:

- naked display identity
- MetaGrab tags
- emotional use cases
- BOT support language
- package eligibility
- relationship contexts
- CI-capable inventory behavior

Naked processing must still retain hidden/admin lineage to the formal source.

## Naked-BLK Review Method

Each BLK must be reviewed as if it may become a standalone customer-facing unit.

For each BLK, KKr must ask:

1. Does this BLK stand alone emotionally?
2. Does this BLK stand alone musically?
3. Does this BLK require prior or later context?
4. Does this BLK have a natural beginning and ending?
5. Does this BLK repeat or mirror another BLK?
6. Does this BLK carry a distinct emotional job?
7. Is this BLK safe for naked front-end treatment?
8. What legal/admin lineage must remain hidden but attached?
